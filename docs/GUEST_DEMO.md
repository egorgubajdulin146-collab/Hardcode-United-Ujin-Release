# Гостевое интерактивное демо

На странице входа нажмите «Попробовать без Ujin». Логин, пароль и доступ к
платформе не нужны. Это работающий LOCAL backend с PostgreSQL, а не готовая
картинка из MOCK: можно создать устройства и сценарий, изменить состояние
эмулятора и посмотреть журнал.

Для первого прохода создайте датчик протечки и лампу из шаблонов. Затем
создайте локальное правило «протечка = 1 → свет = 1» и подайте переход
0→1 кнопками датчика. [Пошаговый сценарий](DEMO.md).

Гостевая область отдельная для каждой браузерной сессии. Обновление страницы
сохраняет её до выхода/истечения срока. Другой гость и обычный пользователь
не получают доступа к её объектам по UUID. После выхода повторный вход создаёт
новую область; прежние данные недоступны. Переход к настоящему аккаунту требует
его выданных credentials, меняет серверную сессию и не переносит гостевые объекты.

## Границы

- 30 минут от начала сессии, до 8 устройств и 8 сценариев.
- У устройства до 20 сигналов и 20 событий, запрос до 64 KiB.
- До 60 изменений в минуту и 300 за сессию. При лимите API возвращает 429.
- Только Java LOCAL. Ujin, внешние Python-процессы, публикации, привязки и
  платформенные сценарии запрещены сервером, даже если оператор включил их
  для настоящих аккаунтов. Чтение Ujin и отправка команд не выполняются.
- CSRF включён; гостевой principal создаётся сервером случайно, не берётся
  из запроса и не является общей публичной учётной записью.
- Набор готовых MOCK-примеров отдельно подписан «Готовые примеры» и не является
  интерактивным гостевым демо.

## Конфигурация и очистка

В Java-приложении `ujin.demo.enabled` по умолчанию false. Штатный runtime overlay
передаёт `UJIN_DEMO_ENABLED=${UJIN_DEMO_ENABLED:-true}`, поэтому на обычном
развёртывании кнопка доступна без ручного редактирования серверной сессии.
Чтобы выключить функцию, задайте `UJIN_DEMO_ENABLED=false` перед Compose up.
Состояние сообщается публичным GET `/api/auth/session` без credentials/token.
POST `/api/auth/demo` требует CSRF и при выключенном флаге возвращает 404.

Штатный logout/истечение HTTP-сессии очищает только записи точного случайного
владельца, в одной транзакции с catalog lock. Данные настоящих аккаунтов и других
гостей не удаляются. Если БД недоступна при очистке либо приложение аварийно
перезапущено, возможны недоступные гостевые записи; их владельца новая сессия
не восстановит. Глобальные ограничения 512 устройств/512 сценариев,
10000 событий/10000 команд/20000 runs ограничивают и такие записи.
Одновременно допускается до 64 гостевых сессий, до 30 стартов в минуту на процесс.
При достижении общего лимита демо временно не принимает новые сессии.
Автоматическая межузловая уборка/распределённые HTTP-сессии не реализованы.

## API

- GET `/api/auth/session`: authenticated, demo, demoAvailable, demoLifetimeMinutes.
- POST `/api/auth/demo`: создать либо сохранить текущую гостевую сессию, 204.
  Если уже открыт настоящий аккаунт — 409; функция выключена — 404;
  лимит — 429. Cookie не включается в JSON, UJIN_TOKEN не создаётся.
- POST `/api/auth/logout`: штатный выход с CSRF, 204.
- Остальные разрешённые Java LOCAL API сохраняют существующие контракты.
  Неразрешённый путь или executionMode даёт 403 `DEMO_LOCAL_ONLY`.

Сохранение состояния после обновления страницы не означает сохранение после
рестарта backend: гостевые HTTP-сессии в памяти и требуют нового входа после него.
