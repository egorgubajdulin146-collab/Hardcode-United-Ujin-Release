# Перенос репозитория

Перенос выполняется с сохранением истории Git. Исходный репозиторий и рабочий
деплой сохраняются до проверки нового репозитория. Репозиторий назначения:
https://github.com/egorgubajdulin146-collab/Hardcode-United-Ujin-Release.
Его исходные ветки `develop` и `main` сохраняются обычным fast-forward push,
если они являются предками переносимых веток.

## Подготовка

1. Завершить review открытых PR и выбрать проверенный SHA `develop`.
2. Проверить чистоту рабочего дерева, состав отслеживаемых файлов и историю
   на наличие секретов. Локальный выданный пакет, `.env`, cookies, ключи,
   дампы БД и каталог `work/` в новый репозиторий не добавляются.
3. Проверить содержимое и права нового репозитория. Если он уже содержит
   коммиты, сначала сравнить истории; принудительная перезапись не применяется.
4. Сохранить локальный Git bundle с ветками и тегами вне репозитория.

## История и ветки

Добавить отдельный remote `destination`, сохранив `origin`. Передать согласованные
ветки `develop`, `main` и релизные теги обычным push. Старые рабочие ветки
автоматически не копируются. Не использовать `push --mirror`.

Коммиты, авторство и история сохраняются при таком переносе. Обсуждения PR,
результаты Actions, настройки GitHub и секреты через Git не переносятся.
При необходимости переноса самих PR и настроек следует использовать штатный
GitHub Transfer вместо копирования Git-веток.

## CI и сервер

- Настроить default branch, права команды и обязательные проверки нового repo.
- Проверить Actions без production-доступов.
- Согласовать источник production-деплоя: одновременно выкатывать из двух
  репозиториев нельзя. Здесь deploy запускается push в `develop`.
- Настроить `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY` и
  `DEPLOY_KNOWN_HOSTS` через закрытые настройки GitHub. Значения не публиковать.
- Обновить clone URL и ссылки README после выбора адреса назначения.
- Сверить SHA релиза, healthcheck и загружаемые assets после первой выкладки.

Копирование Git не переносит PostgreSQL и конфигурацию работающего сервера.
Если сервер остаётся прежним, перенос репозитория не требует пересоздания БД.
