# Публикация показаний в Ujin

После привязки UUID к SN карточка устройства позволяет отправить текущее
LOCAL-показание читаемого сигнала (`r`/`rw`). Команды `w` не публикуются.
Это передача состояния эмулятора; доставка команд устройству остаётся отдельным этапом.

## Настройка назначенного устройства

Публикация по умолчанию выключена. Оператор задаёт разрешённые соответствия
на сервере через конфигурацию Spring. SN, extGuid и apartmentId — строки;
SN используется для чтения, extGuid — для публикации. Не подменять фактические
model/class устройства значениями из примера и не регистрировать его повторно.

Пример отдельного конфигурационного файла без секретов:

```yaml
ujin:
  publication:
    enabled: true
    ust: ${UJIN_PUBLICATION_UST}
    dictionary-delay-ms: 2000
    targets:
      - serial-number: "ASSIGNED_SN"
        ext-guid: "ASSIGNED_EXT_GUID"
        apartment-id: "ASSIGNED_APARTMENT"
        model: "ACTUAL_MODEL"
        publish-class: "ACTUAL_CLASS"
        signals:
          - signal-key: leak
            platform-name: "ACTUAL_CLASS_leak"
            short-name: leak
            # Только для конкретного сигнала с подтверждённым wire-mapping:
            # zero-wire-value: 0.001
```

Секрет UST передаётся только через закрытое окружение процесса. Не включать его
в JSON браузера, репозиторий, URL в отчётах, логи или файлы примеров.
Base URL `UJIN_API_BASE_URL` уже содержит `/api`.
Оператор подтверждает соответствие extGuid/class/apartment/SN по выдаче платформы;
приложение дополнительно проверяет видимость SN в текущей сессии резидента.
Сам факт этой видимости не доказывает соответствие квартиры или право публикации.

Если задан `zero-wire-value`, LOCAL и квитанция сохраняют настоящий ноль;
транспорт отправляет указанное значение, а чтение UJIN-state декодирует его
только для этого SN, local signalKey и полного платформенного имени.
Другие числовые измерения не округляются. Настройку сохраняют при перезапуске.

## HTTP и квитанции

- `POST /api/v1/devices/{id}/publications`:
  `{"publicationId":"UUID","signalKey":"leak","value":1}`.
  Значение должно совпадать с текущим LOCAL-состоянием онлайн-эмулятора.
- `GET /api/v1/devices/{id}/publications` — последние квитанции владельца.
- `GET /api/v1/devices/{id}/publications/{publicationId}` — сохранённая квитанция.
- `POST /api/v1/devices/{id}/publications/{publicationId}/readback` с `{}` —
  повторное чтение результата без публикации. Записи защищены сессией и CSRF.

Перед внешней записью сохраняется PENDING-квитанция в PostgreSQL (миграция V5).
В неё входит неизменяемое назначение, но не UST/пароль. При отсутствующем сигнале
в snapshot сначала публикуется короткое имя, затем после ограниченной паузы полное.
Ошибка первой фазы останавливает вторую. Полный запрос отправляется JSON-телом
`{"data":[{"sn":"EXT","s":"CLASS_leak","v":1,"c":"CLASS"}]}`;
UST, apartment_id и serialnumber=extGuid — в query по контракту UAE-пакета.
Совместимость этого query-параметра проверяется на конкретном стенде.

Статусы: PENDING — отправка началась; CONFIRMED — ожидаемое числовое значение
наблюдалось отдельным resident GET; FAILED — явный отказ; UNKNOWN — потеря ответа,
невалидный ответ или значение не наблюдалось. `observedAt` — время чтения backend,
не время измерения устройства. CONFIRMED подтверждает наблюдение значения,
а не причинность перехода и не выполнение команды/downlink.

Повтор одинакового publicationId возвращает сохранённый результат без отправки;
другой payload даёт 409. Новый ID для того же local device/signal запрещён при
PENDING/UNKNOWN. При обрыве браузер сохраняет ID, показывает неизвестность и
предлагает проверку чтением. После перезапуска квитанции загружаются из БД.
Первые 90 секунд PENDING защищён от readback, конкурирующего с ещё идущей отправкой;
после сбоя процесса разрешается только чтение, без автоматического повтора записи.
Если результат так и не появился, требуется разбор причины; API принудительной
повторной публикации/сброса UNKNOWN пока нет. Ошибки Ujin возвращаются безопасными кодами.

## Проверка

`backend/ujin/gradlew test` покрывает две фазы, 1/0, явный wire-ноль, отсутствие
подтверждения при error=0, ошибку словаря, обрыв POST без повтора, идемпотентность,
сохранённый PENDING, доступ аккаунтов и CSRF. Frontend-тесты проверяют отправку
нулевого значения, потерю ответа и восстановление UNKNOWN-квитанции.
Синтетический upstream не подтверждает доступность реального Ujin.
