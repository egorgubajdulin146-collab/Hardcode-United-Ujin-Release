# Отдельные Python-эмуляторы

Используются модели из выданного пакета hardcodeunited/emulators: core.py и
devices/*.py, скопированы без изменения. server.py — отдельный HTTP bridge.
Java-код не меняется. Ключей, доступа Ujin и сетевого клиента публикации нет.
Это LOCAL-стенд, он не подтверждает интеграцию с платформой Ujin.

```bash
docker compose -f infra/emulators/compose.yaml up -d --build --wait
python3 infra/emulators/smoke.py
curl --fail http://127.0.0.1:18191/state
curl --fail http://127.0.0.1:18192/state
```

На сервере порты доступны только localhost. С рабочего компьютера:

```bash
ssh -N -L 18191:127.0.0.1:18191 -L 18192:127.0.0.1:18192 Ujin
```

## Контракт для backend

Приложение пока к этим процессам не подключено. Для Java на хосте:
датчик http://127.0.0.1:18191, свет http://127.0.0.1:18192.
Для контейнера Java после явного подключения к сети ujin-emulators:
http://leak:8080 и http://light:8080. localhost внутри Java-контейнера —
сам Java-контейнер, не хост. Продуктовый Compose здесь не изменяется.

Оба сервиса: GET /health, GET /state, GET /declaration. Content-Type JSON.
State: {family, serial, executionMode:"LOCAL", values:{имя:значение}}.
serial local-leak/local-light — локальные метки, не SN платформы Ujin.

```bash
# Воздействие на датчик: 0 — сухо, 1 — протечка.
curl --fail -H 'Content-Type: application/json' \
  -d '{"kind":"WET","value":1}' http://127.0.0.1:18191/stimuli
# Команда свету; 0 выключает, 1 включает.
curl --fail -H 'Content-Type: application/json' \
  -d '{"signalKey":"lamp","value":1}' http://127.0.0.1:18192/command
```

Успешный POST200 возвращает текущее состояние модели. Некорректный JSON400,
неподдерживаемая команда/значение422, неизвестный путь404. Ноль передаётся как0,
wire_value0.001 из пакета в этом bridge не применяется. Автоматических тиков
нет: моделируются явные воздействия, питание/таймеры не симулируются во времени.
Состояние в памяти процесса: после restart сбрасывается. Bridge не хранит журнал,
commandId/eventId или receipts и не обеспечивает дедупликацию HTTP-команд.
Для lamp0/1 повтор задаёт то же состояние; протокол событий и дедуп — в backend.

Артуру: добавить отдельный адаптер LOCAL-Python: опрашивать leak /state,
сравнивать leak с предыдущим значением; при изменении запускать существующий
движок, action направлять POST light /command, затем читать lamp в /state.
Нельзя одновременно выполнять действие внутренним Java-эмулятором и Python.
Недоступность сервиса не превращать в нулевое значение или успешную команду.
Текущий UI ещё управляет внутренним Java LOCAL, эти POST его не изменяют.

## Эксплуатация

Отдельная bridge-сеть не подключена к backend. Сетевого клиента Ujin в bridge
нет: устройства создаются с client=None, внешних публикаций нет. Это свойство
приложения, не firewall-запрет исходящей сети. Порты без
аутентификации предназначены только доверенному оператору/адаптеру; не публиковать
их через внешний Nginx. Все контейнеры non-root, read-only, с ограничением ресурсов.
Для остановки: docker compose -f infra/emulators/compose.yaml down.
Данных БД нет; процессный restart возвращает leak0/lamp0.

Smoke проверяет1→1→0, readback, неверные значения, неизвестный путь и запрет
команды читаемому датчику; оставляет leak0/lamp0. Не запускать параллельно демо.
